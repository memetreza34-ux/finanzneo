# Build a complete FinanzNeo Reel

Read first:

1. `.agents/rules/finanzneo-reel-safety.md`
2. `CLAUDE.md`
3. `reels/PRODUKTIONSSTANDARD.md`
4. target Reel `03-szenen/scene-index.json`
5. target Reel `03-szenen/alle-bildprompts.txt`

`CLAUDE.md` wins on production/style conflicts. Stricter Antigravity safety boundaries remain binding.

## AUTOPILOT — mandatory

If the user states that images and final audio are ready and says **„Mach das Reel“**, **„Erstelle das Reel“**, **„Mach es fertig“** or equivalent, treat that single instruction as authorization for one continuous non-destructive production run.

Do not ask `Weiter?`, `Soll ich rendern?`, `Soll ich die Untertitel machen?` or similar normal phase confirmations.

Progress messages are informational only. Continue immediately afterward.

Recoverable validator, TypeScript, timing, layout or render errors are work to fix — not user checkpoints:

```text
diagnose → fix → validate → render → inspect → repeat
```

Continue until **PRODUCTION COMPLETE** or a genuine **BLOCKED** condition.

The production command authorizes the completed MP4 and Antigravity QA. It does not authorize merge, publish, delete, force-push or history rewrite.

## HARD USER-MEDIA GATE

For final production use only:

```text
Images: <TARGET-REEL>/03-szenen/00-ALLE-BILDER-HIER-REIN/
Audio:  <TARGET-REEL>/02-audio/
```

Required image filenames come from the target Reel's own `scene-index.json`.

Before coding/timing/rendering verify:

- every required image exists with the exact expected filename
- no unexpected final image is being substituted
- exactly one readable final audio file exists
- no user media is sourced outside the target Reel

Never substitute from another Reel, `legacy-main/`, Desktop/Downloads, web/stock media, placeholders, previous exports, caches or similarly named files outside the target Reel.

Shared repository code, design-system components, scripts and docs remain allowed. The restriction applies to user-media inputs.

If a required asset is missing/wrong/unreadable/ambiguous:

```text
BLOCKED
Problem: <exact path/file/cause>
Action: <exact user action needed>
```

Do not render a knowingly incomplete final MP4.

## Image-generation boundary

Antigravity generates **no final images**. It may write prompts and inspect user images, but must not call image generation, stock/web search or create placeholder media as a substitute.

Any supplied image that violates a visual requirement and must be regenerated by the user is a real blocker.

## Canonical image presentation — adaptive-safe-fill

The old `contain`-poster presentation is forbidden.

For every image scene:

- use `adaptive-safe-fill`
- fill the available visual stage as much as possible
- do not show a small inset 9:16 poster inside the 9:16 Reel
- do not create a visible rectangular image boundary
- do not use a blurred duplicate image as background
- crop empty seamless background first
- preserve face, object labels, hero object, money/value
- use per-scene `focalX` / `focalY` when necessary

Use `src/design-system/AdaptiveSafeFillImage.tsx` for new productive scenes.

Target vertical layout at 1080×1920:

```text
headlineTop      ≈ 70
visualTop        ≈ 210
visualBottom     ≈ 1515
subtitleBottom   ≈ 280
subtitleLeft     ≈ 60
subtitleRight    ≈ 180
platformUiBottom ≥ 260
```

## Audio and captions — exact final-audio timing

Use only the exact final voiceover from `<TARGET-REEL>/02-audio/`.

Create real word-level `start/end` timestamps from that audio. Never distribute words evenly across sentence duration and never reuse provisional timings as final.

Required in-video caption behavior:

- preferred: one full sentence visible
- maximum: two very short sentences only when semantically necessary
- hard maximum: two visual lines
- current spoken word green; remaining words white
- active word follows its real audio start/end
- previous sentence remains through a short pause
- sentence changes exactly when the next sentence's first spoken word begins
- no dead caption gaps

Use `src/design-system/SentenceKaraokeCaptions.tsx`.

`04-caption/word-timings.json` may be final only with:

```text
timingStatus: final-audio-aligned
```

If exact word alignment cannot be created with available tooling, report **BLOCKED** instead of estimating.

## Universal social caption

Create exactly one publishing caption:

```text
04-caption/caption.txt
```

Use this exact same file unchanged for Instagram Reels, TikTok, Facebook Reels and Snapchat.

Caption requirements:

- strong truthful first-line hook
- concise value / aha matching the Reel
- optional natural save/follow/comment CTA
- **exactly 5 relevant hashtags**
- no platform-specific variants
- no `CAPTION:` or `CTA:` template headers in final text
- no random trend tags, spam or irrelevant `#fyp`
- no invented facts or viral guarantee

Forbidden active files:

```text
04-caption/instagram-reels.txt
04-caption/tiktok.txt
04-caption/facebook-reels.txt
04-caption/snapchat.txt
04-caption/youtube-shorts.txt
```

## Continuous production order

After the hard media gate passes, continue without user checkpoints:

1. pre-flight Git status/branch/HEAD/diff
2. ingest/sync only target-Reel media
3. generate real final-audio word timings
4. derive sentence starts and scene timing
5. implement/finish every Remotion scene
6. frame every user image with adaptive-safe-fill
7. add headlines/icons
8. add sentence-based karaoke captions
9. prepare one universal social caption with exactly 5 relevant hashtags
10. run final Reel validation
11. run TypeScript checks
12. render preview
13. inspect first/middle/last frames, captions, transitions and contact sheet
14. render full MP4 with audio
15. inspect complete MP4
16. check audio target when tooling allows (around -16 LUFS, <= -1 dBTP)
17. fix every recoverable issue and repeat affected checks/renders
18. run Antigravity safety audit
19. commit completed work and create/update draft PR when appropriate
20. report final state

Final validation must use:

```bash
npm run reel:validate -- <TARGET-REEL> --final
```

## Stop conditions

Only genuine blockers may stop Autopilot:

- missing/wrong/unreadable/ambiguous required user media
- supplied image must be regenerated by user
- real final-audio word alignment cannot be produced
- unavoidable external credential/quota/permission failure
- next action requires prohibited merge/publish/delete/force-push/history rewrite
- material content ambiguity cannot be resolved from target Reel files

## Completion response

End only as:

```text
PRODUCTION COMPLETE
```

when the final MP4 exists and final validation, TypeScript, preview, visual/caption review, the universal five-hashtag caption and safety audit actually completed; or:

```text
BLOCKED
```

with the exact blocker and exact user action required.
