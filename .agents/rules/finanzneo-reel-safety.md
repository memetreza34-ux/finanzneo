# FinanzNeo — Antigravity Safety Rules

These rules apply only to Google Antigravity in this workspace.

## Highest-priority project sources
1. Read `CLAUDE.md` completely before changing anything.
2. Follow every linked FinanzNeo production standard unless this Antigravity-only file is stricter.
3. Never weaken existing rules, validators, tests, design tokens, finance calculations or production standards.

## Continuous execution / Autopilot mode — mandatory
When the user states that the required images and final audio are ready and gives a production command such as **„Mach das Reel“**, **„Erstelle das Reel“**, **„Mach es fertig“** or an equivalent instruction, treat that single message as authorization to execute the entire non-destructive Reel production workflow from the current state to the finished production result.

After confirming that the required assets exist, Antigravity MUST continue autonomously through all applicable steps without waiting for another user message:

1. inspect and ingest/sync the user assets
2. validate image filenames, scene mapping and image quality
3. derive real word timings from the final audio
4. derive scene starts and durations from the audio
5. implement or finish all Remotion scenes and animations
6. wire images, headlines, karaoke captions and audio
7. prepare the master caption and the four Reel-platform publishing files
8. run Reel/source-contract validators
9. run TypeScript checks
10. render a preview
11. inspect scene frames/contact sheet/captions/transitions
12. render and inspect the full MP4 with audio
13. measure/check the audio target when tooling allows
14. fix every recoverable problem found during QA and rerun the failed checks/render automatically
15. repeat the fix → validate → render → inspect loop until the Reel satisfies the completion contract or a real blocker remains
16. run the Antigravity safety audit
17. commit the completed work and create/update a draft PR when appropriate
18. report the final production result only after the continuous run has reached completion or a real blocker

### No stage-by-stage waiting
Antigravity MUST NOT pause between normal production phases to ask:

- „Soll ich weitermachen?“
- „Weiter?“
- „Soll ich jetzt Remotion bauen?“
- „Soll ich rendern?“
- „Soll ich die Untertitel machen?“
- „Soll ich die QA starten?“

Progress updates are allowed, but they are informational only. After a progress update, continue immediately in the same execution run. Do not require the user to type `weiter`.

### Recoverable failures are not blockers
A failed validator, TypeScript error, render error, incorrect timing, caption issue or other fixable implementation problem is NOT a reason to stop. Diagnose it, fix it inside the allowed Reel scope, rerun the relevant command, and continue.

### Only real blockers may stop Autopilot
Stop and ask the user only when continuing is genuinely impossible or would cross a permission boundary, for example:

- a required user-created image or the final audio is missing, unreadable or clearly the wrong asset
- a supplied image fails a visual rule and must be regenerated by the user because Antigravity is forbidden from generating replacement images
- an external service, quota, credential or permission prevents a required step and there is no local/repo-safe workaround
- the next action would require merge, publish, deletion, force-push, history rewrite or another prohibited/destructive action
- the user request contains a material ambiguity that would change the financial message or final creative direction and cannot be resolved from the existing Reel files

When blocked, report exactly what is blocking completion and exactly what the user must provide or change. Do not use a blocker as a generic checkpoint.

### Meaning of the production command
The user command to **make/finish the Reel** authorizes the complete production run, including final rendering and Antigravity visual/technical QA. It does NOT authorize merging, publishing, deleting previous work, force-pushing or rewriting history.

The human/user visual review mentioned in project standards is a release/publishing approval boundary. It must not be used as a reason to stop before producing and QA-checking the complete MP4.

## Non-destructive repository policy
- Never work directly on `main`.
- Never merge a pull request.
- Never force-push, hard-reset shared branches, rewrite history, delete branches, delete existing reels or overwrite previous reel assets.
- Create a new branch and a new reel directory for every new topic.
- Existing reels are read-only references unless the user explicitly targets one for repair.
- Do not modify `CLAUDE.md`, `docs/FINANZNEO-IMAGE-WORLD-V3.md`, brand tokens, finance helpers, package versions, lockfiles, CI workflows or shared validators merely to make a new reel pass.
- If validation fails, fix the reel. Do not weaken the validator.
- Do not upgrade dependencies unless explicitly requested.

## Allowed scope for a new reel
Prefer only:
- one new `reels/.../<new-reel>/` folder
- one new `src/reels/<new-reel>/` folder
- one reel-specific asset-sync script
- additive npm scripts
- one additive Remotion composition registration
- `.agents/**`

Any broader change requires a concrete reason and must be reported before editing.

## Pre-flight
Before implementation run `git status --short`, record branch and HEAD, and record `git diff --stat` plus `git diff --name-only`. Never destroy unrelated local changes.

## Post-change safety review
Before claiming completion compare against the recorded starting HEAD. Verify no existing reel was deleted or unintentionally modified, no lockfile/dependency change occurred without permission, and validators/typecheck/preview all succeed.

## Image boundary — Antigravity MUST NOT generate images
The user exclusively creates all actual images for FinanzNeo reels.

Antigravity MAY:
- write `03-szenen/bildwelt.txt`
- write cover and scene `bildprompt.txt` files
- write/update `03-szenen/alle-bildprompts.txt`
- define exact expected filenames and scene numbers
- inspect user-supplied images after they are provided

Antigravity MUST NOT:
- generate `bildwelt-referenz.png`
- generate the cover image
- generate any final scene image
- call an integrated image generator, Imagen, Nano Banana or any other image-generation model
- use web images, stock images or generated placeholders as substitutes
- overwrite or replace a user-provided image

The user creates the world-reference image and all final scene images externally and places the completed, correctly named final images together in:

`03-szenen/00-ALLE-BILDER-HIER-REIN/`

If required images are missing, Antigravity must report the exact missing filenames and wait. If a supplied image is visually inconsistent or incorrect, Antigravity reports the problem to the user and does not regenerate the image itself.

## Final permission boundary
Antigravity may create commits and a draft PR. It must not merge, publish, delete previous work or mark a Reel as user-approved for release without explicit user instruction. A command such as „Mach das Reel fertig“ is sufficient authorization to finish production, render the final MP4 and perform Antigravity QA; it is not authorization to publish or merge.
