FINANZNEO STYLIZED 3D ANIMATED BLACK WORLD — V9

PURPOSE
Create clear real-world-grounded financial explainer scenes. The subject, situation and cause-and-effect must feel believable and immediately recognizable from everyday life, while the rendering remains clearly stylized 3D and never photorealistic. The image is not decoration: it must visually explain the spoken point without requiring interpretation.

BASE LOCKS
- FINANZNEO_WORLD_ID: finanzneo-connected-studio-v3
- FINANZNEO_SERIES_LOCK: finanzneo-same-world-v1
- GENERATED_IMAGE_ASPECT_RATIO: 1:1

CORE STYLE
- clearly stylized 3D animation, never photorealistic
- real-world-grounded situations with believable object proportions and recognizable everyday details
- semi-realistic object structure and materials, but visibly stylized rendering
- soft rounded geometry where appropriate; do not turn real objects into generic toys or finance icons
- premium, clean and polished, but not childish
- content and clarity come before decoration
- no fixed number of supporting objects; use the amount needed to explain the situation completely
- every scene may use a different composition while staying in the same visual world

BACKGROUND LOCK
Use one seamless deep black background as a strict requirement. Keep it clean, minimal and uninterrupted. A believable local scene area such as part of a kitchen, laundry area, desk, counter or bank context may exist around the subject when it helps explain the situation, but it must visually dissolve into the deep-black world. No bright studio background, colored environment or distracting background zones.

EXPLANATION FIRST
- build one coherent explanatory scene, not a collection of isolated symbolic objects
- show the real situation first: what happened, what is affected and what solves or changes it
- make cause and effect visible in the same frame whenever possible
- use familiar real-life objects such as washing machines, invoices, bank documents, calendars, shopping bags, phones, household expenses or account folders when they match the spoken content
- the viewer should understand the intended message within roughly 1–2 seconds even without audio
- abstract symbols such as shields, arrows, coins or vaults may support the explanation, but must not replace the real-world situation
- do not make the viewer decode a visual metaphor

GERMAN LABELS
Short German labels are allowed and encouraged when they remove ambiguity. Attach each label clearly to the exact object or state it describes. Examples: “Notgroschen”, “Girokonto”, “Tagesgeld”, “Reparatur 280 €”, “Dispo”, “Dauerauftrag”, “Urlaub”, “Shopping”. Labels must be short, legible and functional. They are not decorative text.

COLOR LANGUAGE
- emerald green for positive or preferred elements
- warm ivory and soft gray for neutral surfaces
- subtle gold only for money or value
- warm red-orange only for warning, cost or loss
- black background remains dominant

LIGHTING
Use clean soft studio lighting with clear highlights, readable shadows, good separation from the black background and soft contact shadows. Everyday objects must remain easy to recognize and should retain believable material cues.

COMPOSITION
Use the full scene context needed for instant understanding. Show a clear main situation or action plus the necessary surrounding context. Supporting objects are flexible: none, one or several are allowed when they genuinely improve the explanation. Prefer one coherent real-life scene over isolated finance symbols. Avoid clutter, tiny unreadable elements and decorative props.

BRANDS + LOGOS
If a brand, bank, app or logo is relevant to the explanation, keep its key visual identity recognizable but reinterpret it inside the same stylized 3D animated world. Use simplified rounded 3D forms, matching materials and matching lighting. Do not paste a flat real-world logo into the image. Do not reproduce a photorealistic branded product shot, website, app screenshot or realistic UI.

TEXT
Only explicitly requested short German labels may appear. Use labels when they materially improve understanding. No headline, subtitle, CTA or long explanatory sentence inside generated images.

FORBIDDEN
- photorealism, stock-photo look or an image that could be mistaken for a real photograph
- generic finance-icon compositions as the main explanation
- isolated vault + shield + coins + arrow scenes with no concrete real-life context
- abstract visual riddles that require interpretation
- sterile empty product shots with no explanatory situation
- flat pasted real-world logos
- screenshot-like branded website/app UI
- dashboard or app UI as the main composition
- flowchart as the main composition
- tiny boxes, floating info cards or dense technical layouts
- microchip/circuit-board visual language
- clutter or decorative props that do not explain the spoken point
- tiny miniature-diorama framing that makes the important content hard to read

PROMPT LENGTH POLICY
Use medium-length but complete image prompts. Every prompt must be written individually for its exact spoken point; never replace the scene description with shorthand, a generic template sentence or a few keywords. Use this order: concrete real-life scene and cause/effect first, exact German labels second when useful, then style, background, composition and forbidden rules. Give enough specific detail that Google Flow does not need to invent the meaning of the scene.

QUALITY CHECK
Reject and regenerate when the scene is only symbolic, the viewer must interpret what the objects mean, the everyday situation is not recognizable, labels are missing where needed for clarity, important objects look like generic icons, the image becomes photorealistic, the background is not deep black, the scene is cluttered, the visual reads like UI/flowchart, a brand looks pasted/screenshot-like, or the style no longer feels like the same stylized 3D world.

GOOGLE FLOW EXECUTION
Strict single-job state machine. Generate exactly one image at a time, wait for the result, rename immediately, run the quality check, regenerate the same image number on failure, then unlock the next image. Never batch or queue later images.
